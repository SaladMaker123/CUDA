# TASK2：GPU FMA 计算性能分析

## 1. 实验环境

| 项目 | 配置 |
|---|---|
| GPU | NVIDIA GeForce RTX 5070 Ti |
| CUDA Toolkit | 13.0 |
| GPU 架构 | sm_120 |
| SM 数量 | 70 |
| 参考核心频率 | 2452 MHz |
| 参考 FP32 理论算力 | 43.94 TFLOPS |

## 2. 实验目标

使用 CUDA C++ 测量 GPU 的 FP32 FMA（融合乘加）计算性能，重点分析：

- FMA 计算吞吐量及 FP32 执行效率。
- 串行 FMA 依赖链的执行延迟。
- ILP（指令级并行）对计算吞吐量的影响。
- 迭代次数对测量结果稳定性的影响。

## 3. 实验方法

### 3.1 FMA Throughput（计算吞吐量）

每个线程维护 64 个独立累加器，通过大量 FP32 FMA 运算测量 GPU 的计算吞吐量。

| 参数 | 数值 |
|---|---:|
| Threads/Block | 256 |
| Blocks | 1960 |
| 每线程累加器数量 | 64 |
| ILP | 4 |
| N_ITER | 40000 |

一次 FMA 计为 2 FLOPs。

总浮点运算量：

`FLOPs = Threads × N_ITER × 64 × ILP × 2`

有效计算吞吐量：

`TFLOPS = FLOPs / Time(s) / 10^12`

使用 CUDA Event 测量 Kernel 执行时间。

### 3.2 FMA Latency（计算延迟）

通过构造串行 FMA 依赖链，分析计算延迟与指令级并行之间的关系。

实验使用单线程 Kernel，包含三个子实验：

1. D × ILP 参数扫描：72 组测试。
2. 空循环基线：测量基础执行开销。
3. 迭代次数敏感性：分析测量结果的稳定性。

其中：

- D：每次外层迭代中每条累加链的 FMA 次数。
- ILP：相互独立的 FMA 累加链数量。

每次迭代的 FMA 数量：

`FMA/iter = D × ILP`

使用 CUDA Event 记录执行时间，并根据设备参考频率估算 Cycles/iter（每次迭代周期数）。

## 4. 实验结果与分析

### 4.1 FP32 FMA 吞吐量

| 指标 | 实测结果 |
|---|---:|
| Kernel 执行时间 | 208.298 ms |
| FP32 有效吞吐量 | 49.33 TFLOPS |
| 正确性验证 | PASS |
| 静态 FFMA 指令数 | 322 |
| 静态 UFFMA 指令数 | 0 |

SASS 检查确认生成了普通 FP32 FFMA 指令。

实测吞吐量高于基于参考频率计算的理论值，可能与 GPU 动态加速频率有关。

49.33 TFLOPS 为当前 Kernel 的有效计算吞吐量，不作为固定硬件理论峰值。静态指令统计不能替代动态执行次数验证。

### 4.2 FMA 串行依赖延迟

固定 ILP=1，对 D 与 Cycles/iter 进行线性回归。

回归方程：

`Cycles/iter = 1.389 + 3.470 × D`

拟合优度：

`R² = 0.9985`

得到串行 FMA 依赖周期增量估计：

**3.47 Cycles/FMA**

该结果反映当前测试条件下每增加一次依赖 FMA 所带来的平均周期增量，不代表精确的硬件指令延迟。

### 4.3 ILP 对执行效率的影响

固定 D=20，测试不同 ILP：

| ILP | Cycles/iter | Cycles/FMA |
|---|---:|---:|
| 1 | 69.9 | 3.50 |
| 2 | 71.8 | 1.80 |
| 4 | 78.6 | 0.98 |
| 8 | 146.9 | 0.92 |

随着 ILP 增加，平均每条 FMA 的周期成本明显下降。

多个独立计算链能够交错执行，隐藏串行计算依赖，提高 FP32 计算流水线的利用效率。

### 4.4 迭代次数敏感性

固定 D=4、ILP=1。

| N_ITER | Cycles/iter |
|---|---:|
| 1000 | 26.1 |
| 5000 | 15.5 |
| 20000 | 14.4 |
| 50000 | 14.2 |
| 100000 | 14.1 |
| 200000 | 14.1 |
| 500000 | 14.0 |

当迭代次数达到 100000 后，测量值基本稳定在约 14 Cycles/iter。

增加测试迭代次数能够降低固定执行开销的相对影响，提高测量稳定性。

空循环基线约为 0.1 Cycles/iter，但由于编译器可能优化掉空循环，不能直接将其视为真实的循环指令开销。

### 4.5 回归分析

| 回归模型 | R² |
|---|---:|
| 加法模型 | 0.9177 |
| 交互模型 | 0.9774 |
| 固定 ILP=1 | 0.9985 |
| 固定 D=2 | 0.8975 |

交互模型具有比简单加法模型更高的拟合优度，说明依赖链长度与独立累加链数量对执行周期存在联合影响。

固定 ILP=1 的线性模型拟合效果最好，可用于估计串行 FMA 的依赖周期增量。

## 5. 实验结论

1. RTX 5070 Ti 在当前测试中达到 **49.33 TFLOPS** 的有效 FP32 FMA 吞吐量。
2. FMA 串行依赖周期增量估计约为 **3.47 Cycles/FMA**。
3. 提高 ILP 能够有效隐藏计算依赖，降低平均每条 FMA 的周期成本。
4. 较长的迭代循环能够减少固定开销对测量结果的相对影响。
5. FMA 吞吐量与依赖延迟是不同的性能指标，需要分别测量和分析。
