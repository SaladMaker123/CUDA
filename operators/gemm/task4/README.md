# TASK4 — FP32 GEMM 深度优化

## 1. 实验环境

- GPU：NVIDIA GeForce RTX 5070 Ti
- 架构：Blackwell SM120
- CUDA Toolkit：13.0
- 计算精度：FP32 输入、FP32 累加、FP32 输出
- 性能基准：cuBLAS SGEMM

## 3. V0 — Naive GEMM

采用二维线程块，每个线程独立计算输出矩阵中的一个元素，直接从全局内存读取 A、B 矩阵数据并完成乘加运算。

### 分块参数

| 参数 | 数值 |
|---|---:|
| BM | 16 |
| BN | 16 |
| TM | 1 |
| TN | 1 |
| Threads per Block | 256 |

### 性能测试

测试规模：M=N=K=4096。

| 实现 | 执行时间（ms） | TFLOPS | 相对 cuBLAS 性能 |
|---|---:|---:|---:|
| V0 | 49.562 | 2.773 | 8.143% |
| cuBLAS | 4.036 | 34.056 | 100% |

测试采用 CUDA Event 计时，预热 10 次，每轮重复测试 20 次，进行三轮交替测试并取中位数。

### 正确性验证

| 矩阵规模 | 最大绝对误差 | 验证结果 |
|---|---:|---|
| 4096×4096×4096 | 3.585815e-04 | PASS |
| 513×769×257 | 1.621246e-05 | PASS |

### 初步分析

当前实现未使用共享内存或寄存器分块，存在大量重复的全局内存读取。后续将通过共享内存分块提高数据复用率。

具体性能瓶颈将在后续统一进行 Nsight Compute 分析时确认。

## V1 — Shared Memory Tiling

### 优化内容

- 使用共享内存缓存 A、B 矩阵分块，提高数据复用率。
- 每个线程分别搬运 A、B 矩阵中的一个元素。
- 共享内存采用一列 Padding（填充）。
- K 方向分阶段计算，支持非整除矩阵的边界判断与补零。
- 使用循环展开减少循环控制开销。

### 分块参数

| 参数 | 数值 |
|---|---:|
| BM | 32 |
| BN | 32 |
| BK | 32 |
| TM | 1 |
| TN | 1 |
| Threads per Block | 1024 |
| Shared Memory | 8448 B |

### 性能测试

GPU：RTX 5070 Ti，M=N=K=4096。

| 版本 | 耗时（ms） | TFLOPS | 相对 cuBLAS |
|---|---:|---:|---:|
| V0 | 54.902 | 2.503 | 7.385% |
| V1 | 56.415 | 2.436 | 7.142% |

V1 相比同一实例上的 V0 性能下降约 2.68%。

### 正确性验证

| 矩阵规模 | 最大绝对误差 | 验证结果 |
|---|---:|---|
| 1024×1024×1024 | 6.866455e-05 | PASS |
| 4096×4096×4096 | 3.585815e-04 | PASS |
| 513×769×257 | 1.621246e-05 | PASS |

### 实验分析

共享内存分块减少了全局内存的重复读取，但未取得预期性能提升。

可能的限制因素：

- V0 已通过硬件缓存实现部分数据复用。
- 1024 线程的线程块限制了 SM 的理论占用率。
- 每次乘加仍需要两个共享内存操作数，缺乏寄存器级数据复用。
- 每个 K 阶段引入两次线程块同步。

根据线程访问映射分析，当前 Padding 并非消除存储体冲突所必需，暂时保留该布局。
## V2 — Register Blocking（寄存器分块）

### 优化内容

- 增大 Block Tile，每个线程块负责 128×128 的输出区域。
- 引入 8×8 寄存器分块，每个线程独立累加 64 个输出元素。
- 使用 float4 进行全局内存向量化读取。
- A 矩阵采用转置共享内存布局，B 矩阵保持原有布局并采用向量化写入。
- 通过外积计算提高寄存器级数据复用率及指令级并行度。

### 分块参数

| 参数 | 数值 |
|---|---:|
| BM | 128 |
| BN | 128 |
| BK | 8 |
| TM | 8 |
| TN | 8 |
| Threads per Block | 256 |
| Shared Memory | 8192 B |

矩阵尺寸要求：M、N 为 128 的整数倍，K 为 8 的整数倍。

### 性能测试

GPU：RTX 5070 Ti，FP32。

| 矩阵规模（M×N×K） | 耗时（ms） | TFLOPS | cuBLAS TFLOPS | 相对性能 |
|---|---:|---:|---:|---:|
| 1024³ | 0.131 | 16.436 | 25.595 | 64.217% |
| 2048³ | 0.715 | 24.012 | 31.739 | 75.654% |
| 4096³ | 5.654 | 24.309 | 32.716 | 74.302% |
| 8192³ | 45.110 | 24.374 | 33.214 | 73.386% |
| 1024×2048×512 | 0.118 | 18.142 | 25.045 | 72.438% |

### 版本性能对照

测试规模：M=N=K=4096，使用同一 GPU 实例。

| 版本 | 耗时（ms） | TFLOPS | 相对 cuBLAS |
|---|---:|---:|---:|
| V0 | 54.902 | 2.503 | 7.385% |
| V1 | 56.415 | 2.436 | 7.142% |
| V2 | 5.654 | 24.309 | 74.302% |

V2 性能达到 V0 的 9.71 倍、V1 的 9.98 倍。

### 正确性验证

| 矩阵规模 | 最大绝对误差 | 验证结果 |
|---|---:|---|
| 1024³ | 6.866455e-05 | PASS |
| 2048³ | 1.564026e-04 | PASS |
| 4096³ | 3.585815e-04 | PASS |
| 8192³ | 0.000000e+00 | PASS |
| 1024×2048×512 | 3.623962e-05 | PASS |

全部测试通过，不合格元素数均为 0。

### 实验分析

V1 缺乏寄存器级操作数复用，每个线程读取两个共享内存元素仅执行一次 FMA。

V2 通过寄存器分块，每个线程在单次 K 步骤中读取 16 个共享内存元素，执行 64 次 FMA。

| 指标 | V1 | V2 |
|---|---:|---:|
| 每线程累加元素数 | 1 | 64 |
| 每 K 步骤共享内存读取元素数 | 2 | 16 |
| 每 K 步骤 FMA 次数 | 1 | 64 |
| FMA / 读取元素数 | 0.5 | 4 |

寄存器分块使算法层面的操作数复用效率提升 8 倍。结合向量化访存、更大的线程块分块及多个独立累加器，V2 取得显著性能提升。
