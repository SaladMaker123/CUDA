# TASK3：SGEMM 分块参数性能建模

## 1. 实验环境

| 项目 | 配置 |
|---|---|
| GPU | NVIDIA RTX 5070 Ti |
| CUDA Toolkit | 13.0 |
| GPU 架构 | sm_120 |
| SM 数量 | 70 |
| FP32 参考吞吐量 | 49.33 TFLOPS |
| GMEM 实测带宽 | 0.836 TB/s |
| SMEM 实测带宽 | 6.149 TB/s |

## 2. 实验目标

使用 Python 建立 SGEMM 理论性能模型，分析分块参数对计算吞吐量、数据复用和硬件资源占用的影响，为后续 CUDA SGEMM 实现提供候选配置。

## 3. 实验方法

扫描以下分块参数：

| 参数 | 扫描范围 |
|---|---|
| BM=BN | 16、32、64、128、256、512 |
| BK | 4、8、12、16、32 |
| TM=TN | 1、2、4、8、16 |

共计 150 组配置。

模型使用线程数、寄存器、共享内存和指令缓存四项约束筛选配置。

性能上界计算：

`P = min(P_compute, P_GMEM, P_SMEM)`

其中：

- P_compute：考虑计算流水线利用率的 FP32 性能上界。
- P_GMEM：全局内存带宽对应的性能上界。
- P_SMEM：共享内存带宽对应的性能上界。

指令缓存预算、指令大小和发射间隔等参数采用简化建模假设，不能视为实测硬件规格。

## 4. 实验结果

### 4.1 配置筛选

| 项目 | 数量 |
|---|---:|
| 总配置 | 150 |
| 通过约束 | 39 |
| 线程数约束排除 | 80 |
| 寄存器约束排除 | 20 |
| 指令缓存约束排除 | 11 |

### 4.2 最佳理论配置

| 参数 | 配置 A | 配置 B |
|---|---:|---:|
| BM=BN | 64 | 128 |
| BK | 4 | 4 |
| TM=TN | 8 | 8 |
| 估计吞吐量 | 12.298 TFLOPS | 12.298 TFLOPS |
| FP32 参考性能占比 | 24.9% | 24.9% |

两组配置均受到模型中的共享内存带宽上界限制。

### 4.3 性能分析

增大 BM、BN 可以提高全局内存数据复用率，但当性能受到其他资源限制时，继续增加分块大小不一定带来收益。

增大 TM、TN 可以提高共享内存数据复用率，同时增加寄存器需求。

增大 BK 会增加每阶段计算量及共享内存需求。当前模型中，大 BK 还可能因指令缓存筛选条件限制 TM 的选择。

由于部分约束采用建模假设，模拟结果只能用于候选参数分析，不能直接作为真实 GPU 上的性能上限。

## 5. 实验结论

本次模型筛选得到两组并列最优配置：

- BM=BN=64，BK=4，TM=TN=8。
- BM=BN=128，BK=4，TM=TN=8。

两者估计吞吐量均为 12.298 TFLOPS。

后续将在实际 CUDA SGEMM Kernel 中测试候选参数，通过 Benchmark 确定真实性能与最优配置。
